# Code-index — тела BSL

Это не замена графа. Граф нашёл имя и место — сюда за текстом.

Карточка в WebUI: `1C_code_index`. У большинства tools обязателен `repo`. Не выдумывай путь. Сначала `get_stats` (один раз за чат) и подставь алиас из ответа. На ВМ УБД алиас обычно `ubd`.

## Какие tools звать

Держись короткого набора:

| Нужно | Tool |
|---|---|
| Алиас репо | `get_stats` |
| Тело по точному имени | `get_function` (`name` + `repo`, при неоднозначности `path_glob` из графа) |
| Поиск по словам в коде, если имя неизвестно | `search_function` / `grep_body` — узкий запрос, не «по всей базе» |
| Кусок файла по строкам графа | `read_file` |

Не вызывать без прямой просьбы: `bsl_sql`, `list_files`, `get_call_tree` на большую глубину, `find_path` вместо графа, `health`.

Не обходи граф: не начинай с `grep_body` «переплата», если ещё нет имени процедуры.

## Порядок

1. Имя процедуры и путь уже есть из графа.
2. Один `get_function` (или два: расчёт + сборка запроса). Не по всей цепочке callees.
3. Не вызывай `get_function` повторно для той же процедуры.
4. Не крути `code_method_signature` графа, если тело уже есть.

Если имя неуникально — в ответе будут локации без тел. Уточни `path_glob` (путь из графа), повтори один раз.

## Длинные запросы

Функция длиннее ~80 строк (типично `ТекстЗапроса…Часть1`) — не вставляй модуль целиком.

Выпиши:

- откуда берётся оплата / сумма / остаток
- какие таблицы и поля
- как получается результат

Полный текст: «открой файл в EDT по строкам из графа».

## Ответ

Кратко логика своими словами + цитата короткого фрагмента BSL (условие, присвоение, ключевые поля запроса) + таблица мест из графа.

**Источники:** граф УБД и 1C_code_index.
