# DNS Docs — портал документации (только чтение)

MCP ходит в `https://docs.dns-shop.ru` **гостем**. Открытые статьи читаются без логина. Приватные без SSO **недоступны** — так и скажи, не выдумывай текст.

Запись на портал не предлагай (создать/править статью, комментарий, актуальность). Правки — в самом docs.

Это не Confluence, не MDD, не граф УБД и не `1c-docs` (справка платформы). Код и реквизиты конфигурации здесь не ищи.

## Когда звать

- «как работает … по инструкции», «регламент», «найди в docs», ссылка `docs.dns-shop.ru/ViewArticle/…`
- расшифровать аббревиатуру/термин из инструкций (РМД, API, 3P…)

Не звать, если вопрос про владельца объекта (MDD), код/метаданные (граф + code-index), синтаксис платформы (`1c-docs`), wiki Confluence.

## Какие tools звать

Обычный путь «найди инструкцию и прочитай»:

1. Неясный термин / аббревиатура — `dns_docs_glossary_lookup` (`limit` 5–10).
2. `dns_docs_search` по ключевым словам, `limit` 5–10 (макс. 25). Не семантика — обычный полнотекст портала.
3. Из выдачи возьми `id` / `url` / `path`. Несколько кандидатов — покажи список с ссылками, не выбирай молча.
4. Нужен текст — `dns_docs_get` по `article_id` **или** `url` (`…/ViewArticle/{id}`). 1–2 статьи за ответ, не пачкой.

Пользователь дал готовый URL/номер статьи — сразу `dns_docs_get`, поиск не обязателен.

Не вызывать без нужды повторный search после удачного get. После 4–6 вызовов пиши ответ.

## Правила

- Всегда указывай `url` в ответе.
- `answerable: false` — не выдумывай содержимое; скажи, что портал не отдал статью (нет / приватная / сбой).
- Не цитируй многостраничные простыни: краткое резюме + ссылка + ключевые абзацы / шаги.
- Имена объектов 1С из инструкции не выдавай за факт конфигурации — для проверки зови граф / code-index.

## Формат ответа

```
**Источник:** DNS Docs (docs.dns-shop.ru)

| Поле | Значение |

| Путь | … |

Краткая суть / шаги…

**Оговорки:** чего портал не вернул; приватные статьи в v1 недоступны.
```
