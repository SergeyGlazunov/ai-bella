# Query-builder — новый запрос 1С

Карточка в WebUI: `ubd-query-builder` (или синоним). Источник — граф Neo4j той же выгрузки УБД. Имена таблиц в tools: `Справочник.Номенклатура`, `РегистрНакопления.…`.

## Какие tools звать

| Нужно | Tool |
|---|---|
| Состав полей, ТЧ, виртуальные таблицы | `query_fields` |
| Как соединить две таблицы | `query_join_hint` |
| Проверить готовый текст | `query_validate` |
| Замечания по производительности | `query_optimize` |

`query_build` — опциональный каркас. Не отдавай его текст пользователю как готовый запрос. Если вызвал — обязательно перепиши поля/JOIN/ГДЕ сам и прогони `query_validate`.

## Порядок

1. `view_skill`, если рецепта ещё нет в контексте.
2. Уточни таблицы: `query_fields` по каждой нужной (при длинном списке реквизитов — `attributes_limit` / `tabular_section`).
3. Если таблиц ≥2 — `query_join_hint` на каждую пару, где нужен JOIN. Бери фрагменты из `joins`, не выдумывай ПО.
4. **Сам** напиши текст запроса (`ВЫБРАТЬ` / виртуальные таблицы / параметры).
5. Один `query_validate`. Есть `errors` — исправь текст и validate ещё раз (не больше 2–3 кругов).
6. По желанию `query_optimize`, если спрашивают про скорость или виртуальные таблицы.

Стоп: после validate с `valid: true` (или когда errors разобраны явно) — сразу полный текст запроса пользователю. Не вызывай только `query_build` и не заканчивай на нём.

## Чего не делать

- Не подменяй слой code-index: «покажи ТекстЗапроса из процедуры X» — туда.
- Не выдумывай имена реквизитов вне ответа `query_fields` / `join_hint`.
- Не показывай план и «сейчас найду» — первое действие слоя — вызов tool.

## Ответ аналитику

Полный текст запроса (копируемый), кратко какие таблицы и связи использованы, итог `query_validate` (valid / что поправлено). Источник: query-builder + метаданные УБД.
