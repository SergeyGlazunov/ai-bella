# Design: устанавливаемый контур

Date: 2026-10-18  
Status: принят в диалоге, ждёт ревью этого файла  
Approach: один шаблон MCP на все базы; профиль порождает выключенный инстанс; один репозиторий — продукт, стенд — его запущенная копия.

Этот файл — контракт продукта. Его читают до кода и человек, и агент. Операционные детали ночи, которые здесь не изменены, остаются в `For Cursor/LINUX-FIRST-DESIGN.md`. Где документы расходятся, для новой работы верен этот файл: окно до 07:00, статус `waiting`, источник «каталог», установка чистой машины поднимает общий слой.

## 1. Зачем

Репозиторий должен быть комплектом, который на другой Linux-машине ставится и поднимает тот же контур, что работает сейчас. Выгрузки баз необязательны. Инфраструктура под них входит в комплект. Префикс `ai2-` и история правок этой машины в комплект не входят.

Правки оцениваются только так: входят в комплект, не входят, или их ещё не хватает. Оркестратор `contour` — ночная половина комплекта, не отдельный проект.

## 2. Готово, когда

Человек с Linux, Docker Engine и systemd клонирует репозиторий, запускает `bootstrap.sh` и получает отвечающие чат, OmniRoute и MDD. Tools SDMS и Confluence установлены, личных ключей в них нет. Оркестратор и таймер на месте. Баз может быть ноль. Команда `contour add-database` создаёт профиль и выключенные контейнеры выбранной базы из одного шаблона. После появления выгрузки `contour update` включает эту базу и обновляет её.

Живой стенд с томами `ai2-*` эта процедура не переустанавливает.

## 3. Граница комплекта

Хост — Linux: WSL или отдельный сервер. Установщик не вызывает `wsl.exe` и не читает диск `C:`.

**Всегда, и это уже запущено.** Чат и общие MCP. Чат — Open WebUI `:3000` и OmniRoute `:20128`. Общие MCP не привязаны к базе, у каждого один исходник: MDD `:8080`, SDMS и Confluence. В Open WebUI они подключены как tools. Оркестратор `contour`, каталоги `/srv/ai-contour` и systemd-таймер входят в этот же слой. Проект compose общего слоя называется `contour`. Префикса `ai2-` нет.

**На каждую выбранную базу.** Три MCP из одного шаблона: graph, code-index и query-builder. Пользователь задаёт имя, префикс, нужен ли граф и откуда выгрузка: `git`, пакет или готовый каталог. Система дописывает профиль и создаёт контейнеры выключенными. Code-index есть у каждой базы. Graph, Neo4j и query-builder создаются вместе и только если граф выбран: query-builder читает метаданные этой базы и ничего не индексирует. Пока выгрузки нет, контейнеры базы остаются выключенными. УБД, КБ и klon — примеры профилей, не отдельные программы.

**Отдельная машина, по желанию.** Скрипт выгрузки 1С для Windows, если источник базы — пакет. На хост контура он не ставится.

Установка без баз успешна, когда отвечают чат и MDD, tools SDMS и Confluence установлены без личных ключей, и проходит `contour validate`. База добавлена, когда в конфиге есть профиль, пути, порты и выключенные контейнеры её MCP. Контур этой базы работает после появления выгрузки.

## 4. Как появляется база

Добавление базы делает `contour add-database`. Ночной `contour update` новую базу не выдумывает: он обновляет только записанные профили.

Команда спрашивает четыре вещи. Имя — любое. Префикс — предлагает из имени, пользователь подтверждает или меняет; префикс уникален. Нужен ли граф. Откуда выгрузка. Те же ответы можно передать флагами.

Префикс становится именем проекта, контейнеров и томов. Для `ubd` это `ubd-neo4j`, `ubd-mcp-graph`, `ubd-bsl`, без `ai2-`. Пути — `/srv/ai-contour/sources/<имя>` и, для пакета, `/srv/ai-contour/inbox/<имя>`. Порты — следующий свободный блок с шагом 100, начиная с `8100` (`8100`, затем `8200`, затем `8300`): graph `+1`, query `+9`, code-index `+11`. Блок показывается до создания. Контейнеры создаются выключенными (`compose create`, не `up`).

В Open WebUI tools этой базы появляются, когда оркестратор первый раз успешно запускает её MCP. Выключенные контейнеры в чат не подключаются. При запуске они присоединяются к сети проекта `contour`. MDD, SDMS и Confluence к этой команде не относятся.

Пока выгрузки нет, `contour update` эту базу не стартует. Статус базы — `waiting`. Ночь из-за одного `waiting` не становится неуспешной.

| Источник | Выгрузка есть, когда | Ревизия |
|----------|----------------------|---------|
| `git` | fast-forward принёс новые коммиты в `/srv/ai-contour/sources/<имя>` | git SHA, маркер `.contour-revision` пишет оркестратор |
| пакет | в inbox лежит готовый пакет | ревизия пакета |
| каталог | дерево уже лежит в пути профиля и содержит `.contour-revision` | текст маркера |

Нет маркера у каталога — прогон этой базы `failed` до индексации, контейнеры остаются выключенными.

## 5. Ночь

`ai-sync.timer` в 01:30 `Asia/Vladivostok` запускает один `contour update`. Окно записи — 01:30 включительно, 07:00 исключительно. Вне окна новая запись не стартует. Уже идущий индексатор в 07:00 не убивается. Состояние лежит в SQLite на хосте.

Базы идут одна за другой, в порядке профилей в конфиге. Один процесс, один lock. Параллельного прогона нет. Перед каждой следующей базой окно проверяется снова. Если первая заняла время до 07:00, вторая в эту ночь не стартует. Если первая закончила внутри окна, вторая начинается сразу за ней.

Для каждого включённого профиля:

1. Выгрузки ещё нет — контейнеры выключены, статус `waiting`. Это не провал индексации и не трогает остальные базы.
2. Выгрузка есть и она новая, либо прошлый прогон этой базы не дописан. Источник готовится своим способом, дальше путь один: применить исходники, включить выключенные контейнеры нужных слоёв, проиндексировать, проверить, опубликовать ревизию.
3. Code-index индексируется всегда. Graph — только если он есть в профиле. Query-builder поднимается вместе с графом.
4. На время записи закрывается чтение только MCP этой базы. Чат, MDD, SDMS, Confluence и другие базы продолжают работать.
5. Первый успешный запуск MCP этой базы подключает их tools в Open WebUI. Повторная ночь регистрацию не плодит.

Опубликованной считается ревизия, у которой все слои профиля проверены и записаны в SQLite. Непроверенный индекс в статус успеха не попадает.

Новой выгрузки нет, а опубликованная ревизия на месте — база пропускается молча, это не `waiting` и не ошибка.

## 6. Сбой ночи

Docker недоступен в начале прогона — ни одна база не стартует, уходит один алерт.

Дальше каждая база сама по себе:

- `waiting` — первой выгрузки нет. Ночного алерта нет.
- Пропуск — новой выгрузки нет, опубликованное на месте. Алерта нет.
- `deferred` — окно закрылось, пока очередь дошла до базы, или писатель этой базы ещё жив. Индексатор не стартует. Уже идущая база дописывается. Алерт один на ночь, эта база в нём есть.
- `failed` до касания индекса (мало места, битый пакет, git не стянулся, у каталога нет маркера). Предыдущие данные продолжают отдаваться. База в том же алерте.
- `failed` после начала индексации. MCP этой базы остаётся закрытым, непроверенная ревизия не публикуется, исходники на диске остаются. Следующая база начинается, если окно открыто. После успешного повтора открывается только этот MCP.

Повтор той же причины не шлёт второй алерт, пока статус базы не сменился. Итог ночи: есть `failed` — ночь неуспешна; есть только `deferred` — ночь неуспешна, данные не порчены; все базы в `success`, `waiting` или пропущены — ночь успешна.

Повтор одной базы — `contour update --database <имя>` внутри окна, либо следующая ночь. Канала алерта может не быть: тогда текст пишется в журнал хоста, установка из-за этого не останавливается.

## 7. Установка хоста

На машине уже есть Linux, Docker Engine и systemd. `bootstrap.sh` их не ставит.

Команда не вызывает `wsl.exe` и не читает диск `C:`. Создаёт пользователя `ai-contour`, каталоги `/opt/ai-contour`, `/etc/ai-contour`, `/srv/ai-contour`, ставит Python-окружение и кладёт конфиг из примера. Поднимает общий слой и включает `ai-sync.timer`. Базы не создаёт: шаблоны graph и code-index лежат в комплекте, инстансов нет.

Это процедура чистой машины. Чужие тома она не копирует и не пересоздаёт.

### 7.1. Секреты и ключ модели

Установщик генерирует сам: ключ сессии Open WebUI, первичный пароль OmniRoute, ключ, которым WebUI ходит в OmniRoute. Для базы при `add-database`: пароль Neo4j и секрет её MCP. Это внутренние пароли контура.

MDD зашит в комплект. Адрес и данные подключения лежат в установщике, при установке их не спрашивают.

SDMS и Confluence — не секреты хоста. Установка кладёт сами tools. Логин и токен вводит каждый пользователь чата у себя. Общего JWT на машину нет. Пустые личные данные контейнеры не блокируют.

Ключ модели в Open WebUI не кладётся. WebUI ходит в OmniRoute сгенерированным ключом. Ключ пользователя — доступ OmniRoute к провайдеру.

При установке один вопрос: есть ли API-ключ. Пустой ответ не блокирует установку: чат и общие MCP поднимаются, модели нет, пока ключ не добавят командой `contour register-model`. Если ключ дан, установщик спрашивает провайдера из списка комплекта и регистрирует его в OmniRoute. Модель этого провайдера становится доступной в Open WebUI и выбирается по умолчанию, если это первая зарегистрированная. Ключ остаётся в данных OmniRoute на хосте и в git не попадает. Для провайдера, у которого в комплекте помечен Vision Bridge, установщик включает мост параметрами из комплекта. Сейчас это `glm-5.3`: режим `describe`, vision-модель `glm-5.3-flash`. Повторная регистрация — команда `contour register-model`, без нового `bootstrap.sh`.

## 8. Что уже есть и чего нет

Оркестратор — ночная половина. `contour update` уже обходит профили по очереди, тянет `git` или пакет, индексирует слои, не публикует непроверенное и не роняет соседние базы. Схема v2 допускает любое число баз. УБД, КБ и klon в примере — три профиля.

Установки в комплекте ещё нет:

- `bootstrap.sh` ставит только `contour`, не поднимает чат, общие MCP и таймер, и проверяет systemd через `wsl.exe`.
- `contour add-database` нет. Каталоги `deploy-ai2` скопированы руками и содержат `ai2-`.
- Окно в примере кончается в 06:00.
- База без первой выгрузки попадает в `deferred` и в ночной алерт, а не в тихий `waiting`.
- Источник «каталог» в конфиге не описан.
- MDD в compose смотрит на файлы с диска `C:`. SDMS и Confluence описаны как skills, не как tools с личными данными пользователя.
- Вопрос про API-ключ и регистрация провайдера в OmniRoute не делаются.

Вне продукта, даже если код уже есть: второе поколение индексов, универсальный установщик Windows, переписывание индексаторов. Скрипт выгрузки 1С остаётся отдельным куском.

## 9. Один репозиторий

Второй репозиторий не заводится. Git хранит продукт. Стенд — запущенная копия плюс местные данные.

В git: шаблоны, `contour`, `bootstrap`, пример конфига, этот документ, скрипт выгрузки 1С. Не в git: секреты, тома, логи, сгенерированные инстансы конкретной машины, черновики `.tmp-*`. Зачистка перед корпоративным GitHub выкидывает лишнее из этого же репозитория.

Стенд в этом документе — только список отличий, не вторая архитектура. Новое проектируется в продукте, попадает в git, затем на стенд. Подсмотренная на стенде копия в шаблон не переносится.

Отличия машины ADM-SAPHX-TECH, пока она не переведена на комплект: префикс `ai2-`, живые тома, порты, которые уже заняты published-сервисами (в том числе OmniRoute на хостовом `:20129` и MDD на `:8180`). Их нельзя пересоздать этой установкой.

## 10. Как изменение попадает в контур

Этот раздел читают до любого кода.

Изменение бывает трёх видов.

- **Продукт** — это увидит человек, который поставил комплект на чистую машину.
- **Эта машина** — порт, том, префикс `ai2-`, уже запущенный контейнер. В шаблон не переносится.
- **Идея** — абзаца в этом документе нет. В код и в git не идёт. Дашборд мониторинга контейнеров и MCP — идея, пока сюда не добавлен абзац.

В код идёт только продукт, по шагам.

1. **Одна фраза.** Что появится на чистой установке. Если фразу нельзя сказать без «на этом стенде» — это не продукт.
2. **Слой.** Всегда (чат, общие MCP, оркестратор), база (graph, code-index, query-builder) или другая машина (выгрузчик 1С). Слой не выбран — в код не идти.
3. **Абзац в этом документе.** Что добавляется, чего не делает, как проверить. Абзаца нет — кода нет.
4. **Код в этом же репозитории.** Шаблон или команда `contour`, тест на фразу из шага 1. Не ручная копия под `ai2-`. В git не класть секреты, тома, логи, сгенерированные инстансы и `.tmp-*`.
5. **Проверка до стенда.** Тест проходит локально. Это ещё не установленный контур.
6. **Стенд последним**, из этого коммита, и только по явному разрешению. Местная подгонка не копируется в шаблон. Если без подгонки продукт на стенде не работает — вернуться к шагу 3. Если это особенность машины — дописать список отличий в §9.
7. **Один коммит** на фразу: документ и код вместе. В сообщении — фраза из шага 1.

Агент до кода показывает три строки. Нет строк — работу не принимать.

- Фраза: что получит чистая установка
- Слой: всегда / база / другая машина
- Документ: какой абзац меняется

Без явного «да» агент не трогает живой стенд, не заводит второй репозиторий и не реализует идею, которой нет в документе.

## 11. Проверка

Проверяется чистая машина, не стенд `ai2`. Docker и systemd уже стоят.

**Установка без баз.** `bootstrap.sh` заканчивается, не вызывая `wsl.exe` и не читая диск `C:`. Отвечают Open WebUI, OmniRoute и MDD. Tools SDMS и Confluence есть, личных ключей в них нет. `contour validate` проходит, таймер включён. Контейнеров баз нет. Пустой API-ключ установку не останавливает. Если ключ дан, в OmniRoute есть провайдер, в Open WebUI эта модель видна и выбрана по умолчанию, ключа нет в git.

**Добавление базы.** В конфиге профиль: префикс без `ai2-`, пути, блок портов. Code-index создан и выключен. Graph, Neo4j и query-builder есть только если граф выбран, и тоже выключены. В чате tools этой базы ещё нет.

**Ночь.** Нет выгрузки — `waiting`, алерта нет, контейнеры выключены. Две базы с выгрузкой идут по очереди; вторая стартует, только если до 07:00 ещё есть окно. Сбой одной не гасит чат и общие MCP и не публикует непроверенную ревизию. Следующая база в открытом окне начинается.

**Агент.** В коммите на одну фразу лежат абзац документа и код. Секретов, томов, логов и `.tmp-*` в коммите нет.

## 12. Не входит

Второе поколение индексов и blue-green. Универсальный установщик Windows. Переписывание индексаторов graph и code-index. Установка Docker и systemd скриптом комплекта. Переустановка живого стенда ADM-SAPHX-TECH. Дашборд и API управления, пока для них нет абзаца по §10.
