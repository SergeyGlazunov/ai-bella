Дополнительно получен пакет mcp-review-input: исходники MDD с хоста и dist работающего контейнера, код SDMS/Confluence из хранилища Open WebUI, обезличенные примеры и отчёт сборщика. Для BSL и graph подтверждены свойства кода в репозитории, а не соответствие текущим образам стенда. VENDOR.md не содержит проверенных upstream SHA. Для MDD совпадение извлечённого dist с контейнером отмечено сборщиком; соответствие TypeScript этому dist по одним датам файлов не доказано, нужна воспроизводимая сборка перед выпуском.

## 1. Code-index

### 1.1. Repo по умолчанию: подтверждено, нужна доработка

В crates/code-index-core/src/mcp/mod.rs большинство схем используют repo: String; resolve_repo ищет явный алиас. Схемы дополнительных BSL-tools тоже требуют repo. Одного значения по умолчанию в обработчике недостаточно: schema tools/list и десериализация также должны разрешать пропуск.

Предлагаемый контракт: непустой явный repo имеет приоритет; иначе DEFAULT_REPO; иначе единственный зарегистрированный репозиторий. Ноль репозиториев или несколько без default дают понятную ошибку. Неверный DEFAULT_REPO не подменять случайным репозиторием. Пустая строка считается пропуском. Учитывать core-tools, extension-tools и динамическую смену списка репозиториев.

Проверки: пропущенный/пустой repo, явный корректный/неизвестный, неверный default, ноль/один/два репозитория, одинаковое поведение tools/list и tools/call. Формула repo: str = DEFAULT_REPO не является готовым патчем: сервер написан на Rust.

### 1.2. Сократить tools/list: механизм уже есть

CodeIndexServer::with_allowed_tools и apply_tools_whitelist в mcp/mod.rs используют daemon.toml [tools].enabled. Фильтр действует и на tools/list, и на tools/call. В первой очереди настроить профиль BSL без health/get_class/search_class/bsl_sql, сохранив нужные инструменты. Не удалять функции из универсального индексатора.

Пустой enabled=[] выключает фильтр и возвращает все инструменты, а не скрывает все. Отдельно проверить зависимость healthcheck от MCP health; HTTP/операционную диагностику сохранить. Обновить подсказки, ссылающиеся на скрытые инструменты. bsl_sql реализует read-only SQL; его исключение здесь связано с размером набора и целевыми сценариями, не с доказанной возможностью записи.

### 1.3. Пути реквизитов: потребность обоснована, простой фильтр неверен

get_object_profile/find_references/get_data_links нормализуют имя объекта, но не имеют общего контракта адресации его дочерних элементов. Разрезать по первым двум сегментам и взять последний недостаточно: есть табличные части, их реквизиты, измерения и ресурсы. Сокращённая форма может быть неоднозначной.

Предложение: общий разбор owner + вид/путь дочернего элемента, проверка элемента по структуре объекта. Поддержать явный путь Реквизит/Attribute; остальные виды добавлять с отдельными тестами. Неизвестный/неоднозначный путь возвращает объяснение, а не тихо превращается в объект целиком.

from_path в data_links относится к полю ИСТОЧНИКА связи. Входящая ссылка на Catalog.Контрагенты не доказывает обращение к его реквизиту ДисконтнаяКарта. Фильтрация from_path по имени искомого реквизита даст ложные пропуски/совпадения. Для исходящих связей фильтровать точный путь поля владельца; для code_usages использовать member_path там, где он действительно извлечён. Индекс не гарантирует полноту динамических обращений через переменные. Не обещать «все использования реквизита» без доказанного покрытия.

В ответе разделять сведения об owner, точные совпадения member и ограничения покрытия. Фильтр применять до подсчёта total и пагинации, сравнивать сегменты пути, не подстроку. Сначала отдельная спецификация семантики трёх инструментов; это не маленькая правка числа точек.

### 1.4. get_function: порог уже настраивается

В mcp/tools.rs cap_record_body обрезает только тело длиннее max_function_body_chars И длиннее 100 строк. Тогда остаются 60 строк начала и 40 конца. cap.rs задаёт дефолт 15000 символов; daemon_core/config.rs поддерживает [cap].max_function_body_chars. Значение 0 отключает ограничение.

Первый вариант: проверить конфигурацию 45000 символов на представительном наборе процедур, без full=True и без снятия всех лимитов. Учесть общий бюджет JSON, UTF-8 и несколько одноимённых определений: 45000 символов не равны 45000 байтам или фиксированному числу токенов. Изменение также влияет на get_class и другие места применения общего порога. Если настройки недостаточно, отдельно добавить ограниченный параметр на вызов и способ дочитать продолжение. Ускорение вдвое пока не измерено.

## 2. Graph MCP

### 2.1. Мутирующие и служебные инструменты: частично уже решено

1c-mcp-suite/mcp_tool_filter.py применяет профиль core по умолчанию: metadata_v3_stats и code_v3_stats исключаются как дубли. metadata_reload отключён без ALLOW_DESTRUCTIVE_TOOLS. metadata_cypher также закрыт отдельным флагом ALLOW_RAW_CYPHER.

metadata_upsert_file/metadata_remove_file управляются ENABLE_WATCH_TOOLS. В deploy-ai2/mcp_for_1c-ubd и -kb задано ENABLE_WATCH_TOOLS=0, watcher отключён. start.py применяет фильтр после регистрации.

Если на стенде эти методы видны, сначала сверить образ, entrypoint, env, результат tools/list и обновление списка в WebUI. Снимать декораторы без проверки не требуется. Для закрытых методов проверить и прямой tools/call. В конфигурациях с используемым watcher не удалять его зависимости без замены внутреннего пути обновления.

### 2.2. Русские префиксы: общая формулировка проблемы не подтверждается

В server_v3_tools.py ряд методов уже ищет по full_name_eng, full_name_ru, id и kind_ru + '.' + name. Поддерживается, в частности, Справочник.X. Это не доказывает единообразие всех инструментов, но опровергает утверждение «граф всегда требует только английские префиксы» для кода репозитория.

Нужна матрица конкретных опубликованных методов и их аргументов. Исправлять только обнаруженные пробелы. Нормализатор меняет известный префикс, сохраняет имя и дочерний путь, повторное применение не меняет результат. Не подставлять нормализованные имена в произвольные тексты запросов.

## 3. MDD

В переданных src/tools.ts и src/mddClient.ts names уходит в URL без нормализации. Это подтверждённый пробел. Нормализовать известный английский префикс в русский для каждого элемента списка names в metadata_owners и metadata_properties; пробелы по краям убрать, остальную часть имени сохранить. Не переводить properties. Не добавлять транслитерацию, перевод имён или кэш синонимов в эту задачу.

Пример сборщика сравнивает Справочник.EDIПровайдеры с Catalog.EDIProviders и Справочник.EDIProviders. Меняются сразу тип и имя, поэтому отдельно дефект префикса этим примером не воспроизведён. Для проверки нужен Catalog.EDIПровайдеры и Справочник.EDIПровайдеры, а также смешанный список нескольких names. Неизвестный префикс не заменять приблизительно; передать без изменения с понятным описанием поддерживаемых форм.

## 4. SDMS (read)

sdms_get_task возвращает _request GET /tasks/{id}/info без обработки description. Примеры содержат описание 10869 и 61283 символа; второй пример 82741 байт UTF-8. Проблема подтверждена.

Предложение: преобразовывать data.description в читаемый текст с отметкой description_format=text. Использовать HTML-парсер, не regex удаления всех тегов. Сохранить текст ссылок и адреса, границы абзацев, списков, строк/ячеек таблиц, содержимое pre/code и декодирование HTML-сущностей; убрать style/script. Например, соседние ячейки не должны склеиться в одно значение. Остальные поля и конверт ошибок оставить совместимыми.

Не возвращать одновременно полное исходное HTML и очищенную копию по умолчанию: это удвоит ответ. Чистка HTML сама по себе не ограничивает размер длинного полезного текста. Если потребуется лимит, вводить явное усечение и дочитывание отдельно, не молчаливую потерю требований.

## 5. Confluence DC

### 5.1. Ограничение чтения: подтверждено отсутствие лимита, решение уточнить

confluence_get_page возвращает storage целиком. В пакете страницы 4929 и 1414 символов; пример с Draw.io маленький. Конкретный случай 100–300 тысяч символов этими материалами не воспроизведён. Отсутствие лимита подтверждено исходником; нагрузочные проверки сделать на синтетической большой странице.

Предлагаемый обычный режим: max_page_body_chars=40000, include_raw_storage=False. Возвращать читаемое представление отдельно от оригинального storage, с полями format, truncated, original_chars, returned_chars, version, ссылкой на страницу и способом дочитать. Не маркировать очищенный/обрезанный HTML как пригодный для PUT storage.

Тяжёлые drawio/gliffy-макросы разбирать структурно, заменяя содержимое маркером с именем/идентификатором или ссылкой на вложение. Не удалять текст остальных макросов и не обрабатывать вложенные макросы regex. Сохранить таблицы, код и ссылки. Усечение делать в текстовом представлении, не выдавать оборванный XHTML как корректный документ.

Raw-режим должен сохранять оригинал для редактирования, но безграничный ответ снова переполнит контекст. Для больших исходников нужна явная ошибка превышения транспорта или выгрузка/дочитывание по разделам с привязкой к версии. Нельзя подавать усечённый текст в confluence_update_page. Точный контракт получения большого raw согласовать до реализации этого пункта.

Очистку применять в confluence_get_page, не в общем _request: update_page сам читает текущий storage через _request и должен сохранять его полностью при изменении только заголовка. При поиске страницы по title/space новые параметры должны передаваться в повторный вызов get_page.

### 5.2. Необязательный query: подтверждено, небольшая правка

Сигнатура query: str обязательна. Внутри приоритет cql уже есть. Сделать query: str = ""; если cql.strip() заполнен, использовать его; иначе непустой query экранировать для CQL; оба пусты дают bad_args без HTTP. В схеме Tool query больше не required.

Стендовый пример использует query="", поэтому он не проверяет отсутствие параметра. Локальная проверка извлечённых методов с подменой _request подтвердила TypeError при вызове только cql и успех выбора CQL при явном пустом query. Сетевых вызовов не было.

### 5.3. Автоинкремент версии: уже реализован, пункт закрыть

update_page выполняет GET текущего содержимого и при not version_number ставит current+1. Локальная проверка на синтетической версии 7 дала PUT с версией 8; HTTP-клиент был заменён заглушкой. Добавлять тот же механизм повторно не требуется.

Отрицательная версия сейчас проходит как есть. Предложение: явно отклонять отрицательные значения, оставив 0 документированным автоматическим режимом. Если версия в ответе отсутствует/некорректна, возвращать ошибку, не выдумывать 1.

Конфликт версии возвращается стандартной HTTP-ошибкой. Не добавлять автоматическое повторение PUT с увеличенной версией: так можно затереть чужие правки. Более того, текущий auto-режим с новым GET может перезаписать изменения, сделанные после первоначального чтения модели. При изменении тела передавать явную версию на основе прочитанной; при конфликте перечитать и согласовать содержимое. Улучшение этого контракта выделить отдельно, оно шире исходного исправления нуля.

## 6. Оценка эффекта и ресурсов

Новых постоянно работающих сервисов эти изменения не требуют. Нормализация и фильтры обычно малы по затратам; HTML-разбор расходует CPU/память пропорционально документу. Более длинный get_function увеличит размер ответа, сетевой трафик, контекст и время обработки моделью. Сборка Rust-образа тоже требует ресурсов. Утверждение «никак не повлияет» не подтверждено; заметного роста постоянной RAM от предложений не ожидается, нужны замеры.

Из перечисленных удалений 4 в code-index и 5 в graph получается 9 инструментов: при исходных 62 это 53, а не 35. Часть уже скрыта по коду. Точное число и экономию 3000–4000 токенов оценивать по реальному tools/list и способу передачи схем клиентом. Сокращение числа инструментов не гарантирует экономию на каждом шаге или ускорение вдвое.

## 8. Предлагаемая очередь

1. Сверка фактических образов и tools/list BSL/graph; использование готовых фильтров и проба лимита функции на тестовом экземпляре.
2. Небольшие изменения: default repo, необязательный query Confluence, нормализация префикса MDD; корректировка рецептов tools.
3. SDMS: преобразование HTML с проверками сохранности таблиц/ссылок/кода.
4. Confluence: отдельный контракт читаемого и исходного представлений, лимитов и версий.
5. Пути реквизитов: отдельно согласовать семантику и ограничения покрытия индекса, затем реализовывать.
6. После стабилизации стенда вернуться к установщику. Мониторинг остаётся отложенным.

В пункты 1–2 не включать повторную реализацию уже существующей фильтрации graph и автоинкремента версии. Каждый выпуск проверять через tools/list и tools/call, совместимость старых явных аргументов, сохранность результатов и отсутствие повторной индексации без необходимости.
