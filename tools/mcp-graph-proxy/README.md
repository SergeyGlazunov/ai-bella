# Токен-прокси MCP графа УБД

Отдельная дверь к уже работающему графу. Чат, compose и контейнеры стенда здесь не участвуют.

Клиент (Cursor, OpenCode) ходит на этот прокси со своим токеном. Прокси проверяет токен и вызывает граф с `MCP_SHARED_SECRET`. Мастер-секрет на чужие компьютеры не уходит.

Граф по-прежнему слушает только `127.0.0.1:8101` на `adm-saphx-tech`. Прокси читает его локально и сам слушает порт `8110`.

## Поднять

На стенде, из этого каталога:

```powershell
copy .env.example .env
copy tokens.example.json tokens.json
```

В `.env` вписать `GRAPH_PROXY_UPSTREAM_SECRET` — это `MCP_SHARED_SECRET` контейнера `ai2-mcp-metadata-graph`. В `tokens.json` — по строке на человека. Токен:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

```powershell
.\Start-GraphProxy.ps1
```

Файл токенов перечитывается сам, когда он меняется. Перезапуск нужен только если поменялся `.env`.

Скрипт не перезапускает Docker и не меняет существующие пробросы портов.

## Как пустить коллег

Порт `8110` с других машин сам не откроется: его нужно разрешить в файрволе Windows для офисной подсети. Это отдельное правило, действующие сервисы оно не перезапускает.

Клиенту достаточно адреса и личного токена.

Cursor, `.cursor/mcp.json` (файл не коммитить):

```json
{
  "mcpServers": {
    "ubd-graph": {
      "url": "http://adm-saphx-tech:8110/mcp",
      "headers": {
        "Authorization": "Bearer <личный токен>"
      }
    }
  }
}
```

OpenCode — тот же URL и тот же заголовок `Authorization`.

Проверка с другого компьютера: `GET http://adm-saphx-tech:8110/healthz` отвечает `ok`.

## Отозвать доступ

Удалить строку человека из `tokens.json`. Следующий запрос с его токеном получит `401`.
