# Прокси MCP графа УБД

Отдельная дверь к уже работающему графу. Чат, compose и контейнеры стенда здесь не участвуют.

Клиентский токен не нужен. Прокси пускает офисную подсеть `10.0.28.0/24` и обращения с самой машины, а в граф подставляет `MCP_SHARED_SECRET`. Мастер-секрет на чужие компьютеры не уходит.

Граф по-прежнему слушает только `127.0.0.1:8101` на `adm-saphx-tech`. Прокси читает его локально и сам слушает порт `8110`.

## Поднять

На стенде, из этого каталога:

```powershell
copy .env.example .env
```

В `.env` вписать `GRAPH_PROXY_UPSTREAM_SECRET` — это `MCP_SHARED_SECRET` контейнера `ai2-mcp-metadata-graph`.

```powershell
.\Start-GraphProxy.ps1
```

Скрипт не перезапускает Docker и не меняет существующие пробросы портов.

Другая подсеть задаётся в `GRAPH_PROXY_ALLOW` списком через запятую. После правки `.env` прокси нужно запустить снова.

## Как пустить коллег

Windows по умолчанию не принимает входящие на `8110`. Один раз от администратора, только офисная подсеть:

```powershell
New-NetFirewallRule -DisplayName "MCP graph proxy 8110" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8110 -RemoteAddress 10.0.28.0/24
```

Клиенту достаточно адреса. Заголовок `Authorization` не нужен: если он есть, прокси его не использует.

Cursor, `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "ubd-graph": {
      "url": "http://10.0.28.149:8110/mcp"
    }
  }
}
```

OpenCode и Hermes — тот же URL.

Проверка с компьютера в `10.0.28.0/24`: `GET http://10.0.28.149:8110/healthz` отвечает `ok`. С другой подсети прокси отвечает `403`.
